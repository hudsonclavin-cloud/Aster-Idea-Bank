# Said vs Derived
> A scanner for Aster's "labels are derived, not typed" rule: at `62ddb17` it reads 5,007 literals in 121 TypeScript and 10 HTML files and finds 10 display strings typing a value the code already owns (the catalog's "C3 ≤ 25 km²/s²" while compare reads `metadata.feasibleC3MaxKm2S2`; compare's "0.053–0.166" one line above a note that derives its neighbours; the MCP's "5%" margin), TDB−UTC 69.184 s retyped at 7 sites though the core exports it, `'2040-01-01'` typed in 4 files against a cache window that ends 2040-12-31, and 17 quantities with two or more homes.

**Kind:** linter
**For:** Aster
**Run:** from the bank root, `node ideas/22-said-vs-derived/said-vs-derived.mjs /home/user/asteroid-mining-planner --allowlist ideas/22-said-vs-derived/allowlist.proposed.json` (Markdown on stdout; `--format json`, `--strict`, `--min-sig N`, `--cache PATH`, `--no-cache`, `--list-canon`, `--help`; exit 0 clean, 1 failing findings, 2 usage error or an allow-list entry without a reason). `example.txt` is that run, saved. `index.html` shows the same run with filters and a box that scans a pasted snippet with the same code (classic scripts, works from `file://`). Tests: `node --test ideas/22-said-vs-derived/said-derived.test.mjs` (21 tests, Node built-ins, about 5 s) and `node ideas/22-said-vs-derived/ui-check.mjs` (37 checks in headless Chromium through the globally installed Playwright; `check.mjs` runs it for `tools/check.mjs`). ## What it is

Aster holds itself to a rule that a label is read from the computation that produced the numbers: DEC-17-5 (LOCKED) for the compare surfaces, DEC-19.5-8 (PROPOSED) for every date and span label, INV-026 for trust surfaces, and the house line "constants are imported, never re-typed at the call site". Nothing checks it except one regex in one test. `said-vs-derived.mjs` walks a checkout and does four things:

1. **Harvests the canon**, the values the code already owns: every top-level `const NAME = <number | 'YYYY-MM-DD'>`, every first-level field of a top-level `const NAME = { … }` object (so `GRID_PARAMS.tofMinDays = 182.5` and `GRID_PARAMS.depEndJD = utcMidnightToJdTdb('2040-01-01')` are homes), and the `metadata` object at the head of the 34 MB screening cache (14 leaves, among them `feasibleC3MaxKm2S2 = 25` and `screeningWindow.endUtc = 2040-12-31`). At `62ddb17`: 258 homes, each with its file and line.
2. **Reads every string and template literal** in `src/v2/**` (not tests, not `src/v2/prototypes/`) and `mcp/src/**`, plus the visible text and `content`/`title`/`alt` attributes of `v2/**/*.html` and `index.html`. Each literal is classed import, console, error, CSS, code (GLSL), token (no whitespace: keys, ids, paths, data dates) or display. Only display text is read for claims: ISO dates, year spans, unit-bearing numbers (km²/s², km/s, m/s, AU, km, m, days, s, %, deg, kg …, with `10^6`, `10⁶`, `2.5×10^3` and "330 million"), `C3 ≤ 25` (C3 carries its unit by name) and bare decimals. Text inside `${…}` is derived.
3. **Classes each finding** (the first five fail the run unless an allow-list entry with a reason covers them):

   | class | what it means | at `62ddb17` |
   |---|---|---|
   | LITERAL-MATCHES-CONSTANT | a display string types a value a home owns: same dimension, same value in base units, and the constant's name shares a word with the sentence | 10 |
   | LITERAL-DATE-SPAN | a display string types an ISO date or a year span | 2 |
   | RETYPED-CONSTANT | a code literal with ≥ 4 significant figures equals an exported home elsewhere, or is typed in two or more files; three or more such values shared by two files are one copied block | 26 |
   | DUPLICATE-DATE | the same ISO date literal typed in two or more files | 9 |
   | TWO-HOMES | one quantity defined in two or more files (same dimension and value, a shared name word; for a constant whose name carries no unit, the same words) | 17, 7 allowed under the proposed list |
   | LITERAL-WITH-UNITS | a unit-bearing number in display text that matches no home (informational; `--strict` fails on it) | 18 |

4. **Shows the derived side**: 30 interpolations in display text that read a named constant, following one level of indirection inside a file (`PORKCHOP_DEPARTURE_SPAN_LABEL ← GRID_PARAMS.depStartJD, GRID_PARAMS.depEndJD`), and the 9 places code reads a cache-metadata field at run time.

The saved run (`example.txt`, with `allowlist.proposed.json`) ends `Result: 57 failing finding(s) after the allow-list; 18 informational.` The page puts four of the findings side by side with their derived counterpart, lists all 82 with filters, and lets you paste a snippet and see how each string is classed and matched.

- **S17-F2** (`SLICE_17_FOUNDING.md:716-719`; `STATUS.md:534`, C16): cache and view screen different spans, both once labelled 2026–2040, "still unfixed".
- **STATUS.md:417-425**, Slice 19 item 1, the literal "Grid spans 2026-2040" called an honesty defect.
- **INV-026** (`INVARIANTS.md:200`) and the bank's `BRIEFING.md:46` ("Constants are imported, never re-typed at the call site") and `:109` ("Linting tools that catch … literal labels … are wanted everywhere and exist nowhere").

What exists: `tests/v2-derived-span-labels.test.mjs` asserts by regex that one label in `porkchop/main.ts` is templated and that `screeningWindowLabel` formats full dates; `compare/main.ts:956` reads the threshold from the cache. Nothing checks the other surfaces, the MCP's strings, or numbers typed into code beside the constant that owns them. The neighbouring deposits: idea 04 (Rule One) does this job for Skyhook's prose against `rev_a.json`; idea 10 (Edge of the Grid) measured the S17-F2 incidence and first reported the STATUS item stale.

Alternatives I weighed:

- **One regex per known label**, the existing test's approach. It catches today's string and nothing written tomorrow, and cannot say where the value lives.
- **An ESLint rule on the TypeScript AST.** Precise, but needs `typescript`/ESLint installed and a lint configuration Aster does not have, and the bank's rule is Node built-ins only. I used the TypeScript parser the other way round: as the test oracle for my own lexer (below).
- **A render check**: load each page, read the numbers on screen, compare with the constants. Closest to what a person sees, but it needs a browser, the 34 MB cache and every route's data, and it cannot point at a source line.
- **This**: a small lexer that knows template nesting and regex literals, a canon harvested from the same checkout, and matching by dimension, value and a shared name word. It runs in under a second on the checkout, needs nothing installed, and every finding names the line to change and the home to read from.

## How it works

**Lexer** [Certain for the files tested]. A hand-written TypeScript lexer (`lex` in `said-derived.js`) tracks strings, template literals with nested `${}` (templates inside expressions inside templates), comments, regex literals (a `/` starts a regex after an operator, `(`, `,`, `=`, `return` and similar, and is division after an identifier, number, `)`, `]` or `}`), and a stack of open brackets that records, for every literal, the chain of calls it sits in (`console.warn`, `new Error`, `h`) and the object key it is the value of (`style`, `width`). Escapes are cooked (`km²/s²` reads as km²/s²). On all 121 scanned files at `62ddb17` its literals agree with the TypeScript 6.0.2 parser's, position and cooked text, every one (a test; a one-off run over the 342 TypeScript and JavaScript files in `src/v2`, `mcp/src`, `tools` and `tests` also agreed on all 20,899).

**Classification** [Likely]. In order: an import specifier (after `from`/`import`, or inside `import()`/`require()`); an argument anywhere inside `console.*()`; inside `new …Error()` or after `throw` (developer-facing; refusal reasons that reach a person are not thrown errors in Aster and stay display); CSS (the value of `style`, `*Style` or a known CSS property key, or text that is a list of `property: value` declarations with known property names, or a CSS function such as `rgba(` or `linear-gradient(`); GLSL (`gl_FragColor`, `void main(`); a token (no whitespace after `${}` is replaced: keys, ids, class names, URLs, file paths, data dates), except a bare year span such as `'2026–2040'`, which is display; everything else is display. Literals joined by `+` are read as one sentence for context and name words.

**Claims** [Certain for the grammar, Likely for coverage]. In display text: ISO dates; year spans `YYYY–YYYY` (en dash, hyphen, "to", "through", →) and half spans beside an interpolation; numbers followed by a unit, with an optional comparison (≤, <, ~, "up to" …), range (`300–350 s`) and multiplier ("330 million km"); single-letter units (m, d, h, s, t) need a space, so "1840s" is a decade; `C3 = 21–29` carries km²/s² by name; bare decimals (`0.14`) are read only to be matched, and never reported unmatched. Unit scales: km = 1000 m; 1 AU = 149,597,870,700 m exactly (IAU 2012 Resolution B2), so the cache's `aDeltaKm = 7,479,893.535` is 0.05 AU to the last digit; km/s = 1000 m/s; % against a `*_FRACTION` divides by 100.

**Matching** [Likely]. A constant's dimension comes from Aster's own name suffixes (`Km2S2`/`KM2_S2` → C3, `_KMPS` → speed in km/s, `_MPS` → m/s, `_MS` → ms, `_KM`, `_M`, `_AU`, `Days`/`_DAYS`, `_S`/`SECONDS`, `_DEG`, `_RAD`, `_FRACTION`, `ALBEDO`, `_PX`; `JULIAN_DAY`/`JD` is an epoch, not a duration). A display number matches a home when the dimensions agree, the values agree to 1 part in 10⁹ in base units, and the constant's name shares a significant word with the sentence (camelCase and underscores split, units and generic words such as MAX, DEFAULT, THRESHOLD dropped, plurals folded, "reflectivity" read as albedo and Δ as delta, and words agreeing on a five-letter prefix such as feasible/feasibility). The word rule is what keeps "of 1 AU" (Earth's orbit) from matching `SPATIAL_GRID_CELL_SIZE_AU = 1`; the run shows such equal-but-unrelated homes on the finding instead of hiding them. Homes are listed data first (cache metadata), then exported, then local.

**Duplicates** [Certain for the arithmetic]. Significant figures are counted as written (integer trailing zeros do not count: `946_728_000` has 6, `86_400` has 3, `0.150` has 3). The default of 4 is a choice: at 3, `--min-sig 3` adds 16 sites, 7 of them the colour channel `255` and 6 the `86_400` that `SECONDS_PER_DAY` already exports. A date group whose sites include exactly one named home reports only the copies; with two or more homes every site is reported. A date group also names any cache date in the same year on another day, which is how the run shows S17-F2 without being told about it. TWO-HOMES pairs are joined into groups (three route runtimes defining one camera constant are one finding).

**Allow-list** [Certain]. `{"entries":[{"id","reason"}]}`; an id names one finding (`class|path:line|literal`) or one literal anywhere in a file (`class|path|literal`). A reason shorter than 8 characters is an error: the entry suppresses nothing and the run exits 2. Entries that match nothing are listed as stale. `allowlist.proposed.json` is my proposal of 7 entries, all renderer tuning that no person reads as a number; it is not agreed by anyone.

**Data** [Certain]. The CLI reads a live checkout, using `git ls-files` when the directory is a repository of its own (so a scratch file in the working tree is not scanned) and reports the commit and whether the scanned paths are dirty. The cache is read only for its first 64 KB. For tests that run without the checkout, `build-data.mjs` writes `snapshots/aster/`: a miniature Aster tree with the same paths and line numbers, 5 whole files copied by the bank's `snapshot.mjs`, 7 files excerpted (listed line ranges verbatim, every other line empty), and `docs/lambert-screen-cache.json` cut to its `metadata` object with `--pick`; each has a provenance sidecar at `62ddb17`. The builder refuses an excerpt that cuts a string, template or comment open, or whose literals or harvested canon differ from the full file's on the kept lines. `page-data.js` is the same run as `example.txt`, written by `--emit-page-data`; the page computes nothing from it but filters, and its snippet box runs `said-derived.js` against that canon.

## Honest assessment

- [Certain] The lexer reads Aster's TypeScript exactly as the TypeScript parser does on all 121 scanned files, and the findings in `example.txt` are reproducible byte for byte from the checkout at `62ddb17`.
- [Certain] Every finding below was opened in the file at the line given. The ten LITERAL-MATCHES-CONSTANT findings are values typed into text that a named home holds; whether each should be read instead of typed is the maintainer's call, but none is a coincidence of digits.
- [Likely] The word rule and the dimension-from-suffix rule are heuristics with a bias toward silence. Known misses at `62ddb17`: two homes whose names share no word (`DEFAULT_ABSOLUTE_KM2S2 = 25` in `porkchop/segment-windows.ts:91` against the cache's `feasibleC3MaxKm2S2`, the seam the 2026-08-07 audit flagged as R-03); the third home of the compare cap (`SELECTED_BODY_SET_CAP`, `ui-store/store.ts:35`), whose words differ from the other two; a threshold with no name at all (`compare/main.ts:306` `conditionCode >= 7` and the label "(code ≥ 7)" at `:309`); numbers spelled as words ("up to five asteroids" in `v2/compare/index.html`); and a number built by arithmetic in a label from two literals. A finding is evidence that a literal stands where a derived form is available, not proof that the literal is wrong today: every value matched is currently equal to its home.
- [Likely] Classing error messages as not-display is right for Aster today (refusals are envelope fields, not exceptions), and would hide a thrown message that a page shows to a person.
- [Certain] The proposed allow-list is mine. It allows only renderer tuning; it does not decide anything for Aster.
- [Certain] The tool never writes to the checkout: its outputs are stdout, `--out` and `--emit-page-data`. `build-data.mjs` only reads Aster (through the bank's `snapshot.mjs`, which runs read-only `git` commands there).
- **Rough edges.** Line-numbered allow-list ids go stale when a file shifts, and line-free ids can silently cover a new copy of the same literal in that file. The page's snippet box scans one file, so it cannot show duplicate dates or two homes. HTML scanning is regex-based and sees only the thin entry shells Aster has. The lexer does not understand JSX (Aster has none). `--list-canon` prints tab-separated text, not a table.
