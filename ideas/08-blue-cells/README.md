# Blue Cells
> Reads the Skyhook financial workbook's 14 × 3 input ladder straight out of the .xlsx with nothing but `zipfile` and `xml.etree`, writes it as one JSON artefact carrying the file's sha256 and the md5 that `finance/decision_grid.json` records, and reports what the committed file stores: 146 formula cells and zero computed results. The "post-fix workbook results" in `docs/DECISION_LOG.md` are not stored in this file, nor in any version of it since the fix; they follow from its formulas, which this deposit's tests evaluate on the extracted inputs and reproduce (121.83× / 609 t / $8,741M / Y9 / Y7; and item 8's NPV −$3,883M when the sheet's cash-flow row is discounted as `skyhook_finance.npv_M` does).

**Kind:** tool
**For:** Skyhook
**Run:** from the bank root, `python3 ideas/08-blue-cells/ladder_export.py [any.xlsx]` prints the report for the snapshot workbook or another copy (`--out ladder.json`, `--js page-data.js`, `--format json`, `--provenance <sidecar>`, `--rows-map <json>`, `--census`; exit 1 is a refusal, exit 2 an input it cannot read or an output it cannot write, exit 3 a bug). `example.txt` is the saved run. `index.html` shows it and reads a workbook you drop on it (works from `file://`, nothing uploaded). Tests: `python3 -m unittest discover -s ideas/08-blue-cells -p 'test_*.py'` (62 tests, about 3 s), `node --test ideas/08-blue-cells/bluecells.test.mjs` (23 tests, about 1 s), `node ideas/08-blue-cells/ui-check.mjs` (56 checks in headless Chromium via the global Playwright; `check.mjs` runs it). Rebuild derived data and fixtures with `python3 ideas/08-blue-cells/build_data.py /home/user/skyhook`.
**Made by:** Quire

## What it is

`tools/financial/skyhook_financial_model.xlsx` is Skyhook's financial workbook. Its README sheet gives the legend: *BLUE = hardcoded inputs · BLACK = formulas · GREEN = cross-sheet links · YELLOW fill = key assumption needing attention*. The blue cells are the conservatism ladder (fourteen assumptions × Conservative / Baseline / Optimistic), the shared Rev A design point and two physical constants. Everything else is a formula over them.

`finance/skyhook_finance.py` is "reconciled, by construction, to the corrected workbook" by reading those cells with openpyxl; nothing else, and no browser, can. `ladder_export.py` reads the `.xlsx` (a zip of XML parts) with the standard library, recording each cell's reference, type, formula, cached value and colour. It then:

1. **Extracts the ladder** keyed by `skyhook_finance.py`'s own row map (read with `ast` by `build_data.py` into `snapshots/ladder_rows.json`, never retyped). A row whose column-A label does not say what its key means is refused, naming the row and both labels; `example.txt` refuses `fixtures/shuffled_assumptions.xlsx` (rows 5 and 10 swapped) and the pre-fix workbook (row 3 labelled a derate).
2. **Writes `ladder.json`**: the 42 ladder cells with raw text, references and notes; the design point (B19:B28) and constants (B32:B33); the workbook's sha256, md5, writer and `calcPr`; the per-sheet census; the guards and checks. No timestamp of its own, so two runs give the same bytes.
3. **Counts what the file stores**: per sheet, formula cells, how many of them hold a cached result, literal numbers, and blue, green and yellow cells. The committed file holds **146 formula cells and 0 cached results**, and so does every version since the fix commit `2c27b05` (`2c27b05`, `9bdb224`, `138a9bd`, `8cff680`, `5719c0e`; `34935cb` still holds the last). openpyxl 3.1.5 wrote it, never calculates, and set `calcPr fullCalcOnLoad="1"` so a spreadsheet recomputes on open. Any number quoted as a "workbook result" was computed somewhere else.

Before the fix it was different. Blob `46bc02e` (added in `e0ff4d8`, moved unchanged in `7bb5b5f`, the fix's parent; committed here as `fixtures/pre_fix_7bb5b5f.xlsx`) was written by LibreOffice 24.2.7.2 and stored **134 formula cells with 134 cached results**: the pre-fix ladder's Conservative at 2.0 km/s, 2 × `B11` = 48.2, capex `B4` = $7,085M, payback `B16` = Y15. `2c27b05` rewrote the file with openpyxl and every stored result went. No version in the repository has stored the post-fix figures.

- `finance/decision_grid.json` carries `workbook_md5` (`5ccdee4d…`), hashed from raw bytes by `export_grid.provenance_md5` (`finance/export_grid.py:88-94` comment and `_TEXT_SUFFIXES`, `:97-113` function). Closing that loop without openpyxl needs a reader that hashes what it read.
- `BRIEFING.md` §4: each project "has been bitten by a number quoted from memory". Two browser tools hardcode this ladder's `launch: 2500 / 1500 / 800`: `tools/sims/skyhook_calculator.jsx:20-22` (idea 04's README, `:45`) and the program site's calculator (`skyhook_program_site.html:1135`). Five other candidate ideas needed the ladder as JSON.

What exists (`load_ladder_from_workbook`, `export_grid.py`'s hash, `test_finance.py`'s derate check) needs openpyxl or never reads the file, and none says what the file stores. Alternatives weighed: (a) a hand-written `ladder.json`, with no drift detection; (b) `skyhook_finance.py` writing it as a side effect, keeping the dependency and never looking at cached values; (c) a general xlsx-to-JSON converter, which returns the wrong row's number under the right name once the sheet moves; (d) this: a reader for *this* workbook, keyed by the finance module's row map, that refuses on mismatched labels, hashes what it read and counts what the file stores. The judges valued the census most; no code path in Skyhook produces it (openpyxl could with `data_only=True`, as a test shows; Skyhook uses `data_only=False`).

## How it works

**Zip and XML** [Certain]. Python uses `zipfile` and `ElementTree` by local tag name. The JavaScript walks the central directory (scanning back for its end record, past any archive comment), inflates through an injected inflater (Node's `zlib`, the browser's `DecompressionStream`), checks every size and CRC-32, and refuses ZIP64. Each XML part must decode as strict UTF-8 and pass a well-formedness check before the regexes read it: tags nest and close, one root, no stray `<` or `&`, quoted attributes, no control characters but tab, CR, LF. Expat checks more (duplicate attributes, name characters, undeclared prefixes). Element prefixes are then dropped (`<x:c>` reads as `<c>`), both quote styles are read, and a sheet's relationship id is found by namespace URI, whatever its prefix.

**Exit codes** [Certain]. **1** is a refusal: the sheet does not hold the ladder where the row map says. **2** is one line on stderr for an input it cannot read or an output it cannot write. Inputs: not a zip, a missing part, malformed XML, a cell outside the numeric grammar, a malformed row map or sidecar, or a damaged member (`zlib.error`, `BadZipFile`, `EOFError`, `RuntimeError`, `NotImplementedError` become a `WorkbookError` naming the member; the JavaScript wraps its inflater's error and a `RangeError` the same way). Outputs: `--out`/`--js` in a missing directory or at a directory, or a standard output whose reader has gone, each as `ladder_export.py: cannot write <path> — <reason>`. **3** is anything else, a bug, with its traceback; `main()` wraps everything after argument parsing, so nothing leaves as Python's default exit 1.

**Cells** [Certain]. Each `<c>` becomes `{ref, col, row, t, s, formula, cached, kind, value, raw, font_rgb, fill_rgb}`. A cell with `<f>` is a formula whatever its `t`; its cached value is a non-empty `<v>`, else `None`. `t="s"` indexes the shared strings, `inlineStr` joins the `<t>` runs, `str`/`b`/`e` are string, bool, error; anything else with a `<v>` is a number, raw text kept so `1` and `0.465` print as the sheet has them. `<c t="n"/>` is empty; `<v>0</v>` is zero. Colour: `s` indexes `cellXfs`, then `fonts` and `fills`, and the RGB part is compared with `0000FF` (blue), `008000` (green) and a solid `FFFF00` fill (yellow).

Both readers use one numeric grammar [this tool's choice]: optional sign, ASCII digits with optional fraction (or a bare fraction), optional exponent, finite. `float()` alone would take `NaN`, `inf`, `2_500` and Arabic-Indic digits, and `Number()` would take `0x9C4`; no spreadsheet writes them, so each is a `WorkbookError`. Shared-string, style, font and fill indices must be ASCII digits (Python would read `-1` as the last entry, JavaScript `16.0` as 16). A shared-string index past the end is a `WorkbookError`; a style past the end of `cellXfs` means no colour. The JSON writer uses `allow_nan=False`.

**The ladder** [Certain for the read; the guard is this tool's choice]. `snapshots/ladder_rows.json` holds, from `skyhook_finance.py` at `34935cb`, `_LADDER_ROWS` (lines 56–71: keys → rows 3–16), `SCENARIOS` (52), `cols` (114) and the sheet name (113). The header row (A = `Parameter`) must name each scenario column; each row's label must contain its `LABEL_GUARD` fragment (`construction_launch_per_kg` → "launch price during construction", …; one table in both twins, which a test checks); each cell must be a literal number. Misses are collected and refused with what would help. The design point and constants are the rows with a string in A and a number in B under `SHARED DESIGN POINT` and `PHYSICAL CONSTANTS`, keyed by a slug of the label (`CoM altitude (km)` → `com_altitude_km`).

**Earth radius.** `Assumptions!B33` is 6371 km (`physics/skyhook_physics.py:40`'s `R_EARTH_KM`), so `Design Calcs!B3` = 6981 km; `rev_a.json`'s `com_radius_km` is 6988 (R_E = 6378). Idea 01 (Tip Match) documents the two radii. A test pins B33 + B19 ≠ `com_radius_km`.

**Guards, checks, census** [Certain]. Two **guards** are enforced by refusal (rows where the map says with matching labels; 42 literal cells), so the report lists them as "held". Four **checks** are reported, not enforced, since a restyled sheet still carries the right numbers: ladder cells in the blue font, no blue formula, every green cell a cross-sheet formula, a design point found. `--census` prints the file-level part only, so it reads a workbook the row map refuses.

**Hashes** [Certain]. sha256 and md5 of the raw bytes, as `provenance_md5` hashes a `.xlsx` (`export_grid.py:110-113`), so the md5 equals `workbook_md5`. The JavaScript MD5 is RFC 1321 written out; sha256 comes from WebCrypto.

**The page** computes nothing. `page-data.js` is `ladder.json` as a compact classic script from the same `--js` run (a test checks they are equal). A refused or unreadable drop shows the message and no ladder. At phone width the tables stack into labelled rows.

**Data.** Raw snapshots, taken from the bank root with the `--note` each sidecar records:

```

```

The workbook's sidecar records `34935cb`, blob `3fa20f9`, and that the bytes equal the committed blob. `snapshots/ladder.json` is this tool's output (`--provenance <workbook sidecar> --out … --js page-data.js`), with a `--sidecar-only` sidecar. `build_data.py` derives `snapshots/ladder_rows.json` and `snapshots/DECISION_LOG.md` (lines 45–57, items 6–8, other lines empty so `file:line` matches), both with `--sidecar-only` sidecars, and three fixtures: `shuffled_assumptions.xlsx` (14,601 bytes, rows 5 and 10 swapped, chart removed); `recalculated_by_libreoffice.xlsx` (18,214 bytes; `soffice --headless --convert-to xlsx`, values reproducible, bytes not); `pre_fix_7bb5b5f.xlsx` (20,983 bytes; the checkout is shallow, so a read-only `gh api` GET, kept only because it hashes to blob `46bc02e`). `fixtures/malformed_cases.json` is hand-written: 21 one-member edits (`NaN` in `B5`, shared-string index −1, `sheet2.xml` cut 50 bytes short, …) applied at test time.

- [Certain] Extraction, guards and error handling do what this README says; the sabotage tables show which tests notice which break.
- [Likely] The reader is built for this workbook's shape (one ladder under `Parameter`, labels in A, notes in E). - [Speculative] Committing `ladder.json` or regenerating it in CI is taste; it is byte-stable, so either works.
- [Certain] This is an idea-bank prototype. It has not been through Skyhook's Rule 1 canon review, a verification memo or the pytest suite. pytest is absent here, so the tests are `unittest`; openpyxl 3.1.5 is present and one test uses it.
