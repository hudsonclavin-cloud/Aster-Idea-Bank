Blob Basis

A provenance hash can be checked only if you know which bytes it was taken on. For one text file in a git checkout there are six candidates: the working copy and the committed blob, each as it is, with CRLF folded to LF, and with a CR put before every bare LF. They hash differently. This page shows them for one Aster fixture, places every recorded hash in two of Aster's provenance files and one of Skyhook's, and lets you check a copy of your own.

      Check a copy of your own

      Pick a file (it is read in this page, never uploaded), or try a sample. A browser has no git, so the blob basis needs the committed blob id: paste the output of git rev-parse HEAD:<path>. If one of this copy's three forms has that id, its bytes are the committed blob's, and all six bases follow.
