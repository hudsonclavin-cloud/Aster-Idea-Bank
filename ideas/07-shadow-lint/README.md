# Shadow Lint
> For every number a PartForge FLIGHT loads row feeds its engineering check, says whether the declared geometry can see it. Over 14 fixtures from the PartForge checkout, 89 inputs feed the checks and 29 of them (all 17 loads, pressures, speeds, altitudes and strengths, plus six lengths, five thread sizes and one bolt count) have no geometric shadow; given an attempt and its retry, it flags any input that moved while the code outside comments stayed byte-identical, which is the retry failure mode PartForge's own evaluation says nothing detects today.

**Kind:** linter
**For:** PartForge
**Run:** from the bank root, `node ideas/07-shadow-lint/shadow-lint.mjs ideas/07-shadow-lint/snapshots/bulkhead.scad` (one file: the shadow table) or `node ideas/07-shadow-lint/shadow-lint.mjs ideas/07-shadow-lint/snapshots/motor-retainer.scad ideas/07-shadow-lint/snapshots/motor-retainer.retry.scad` (two files: the attempt diff); `--json` prints an envelope in the shape of PartForge's headless CLI, `--help` the usage; exit 0 no findings, 1 findings, 2 refused, 3 usage. `example.txt` is saved output of seven runs. `ideas/07-shadow-lint/index.html` shows the same findings in a browser and lints pasted text (classic scripts, works from `file://`, no network). Tests: `node --test ideas/07-shadow-lint/shadow.test.mjs` (24 tests, Node built-ins, about 2 s) and `node ideas/07-shadow-lint/ui-check.mjs` (25 checks in headless Chromium with the globally installed Playwright; `check.mjs` runs it for `tools/check.mjs`). `build-data.mjs` re-derives the excerpts under `snapshots/` and `findings.js` from a PartForge checkout.
**Made by:** Sciagraph

## What it is

PartForge's flight grade works like this: the model writes a `.scad` file with a commented `FLIGHT` block that declares critical extents, turned diameters, bores, hole patterns, gauges and *loads rows*; the app compiles the file, measures the declared geometry on the mesh (its "CMM"), and recomputes each loads row's engineering check (Lamé hoop stress, fin flutter, thread strip, bolt shear) from the numbers in the row. A failing row goes back to the model as a retry prompt that ends "correct the inputs if they were wrong; keep the check."

That sentence is the problem this tool is about. The CMM measures a bore. Nothing measures `force_N`. When a bolt-shear row fails, the model's cheapest fix is to lower `force_N` from 20,000 to 12,000, leave the geometry byte-identical, and pass. Shadow Lint does two things about it:

1. **One file.** For every input of every loads row it prints a class and a witness:
   - `WITNESSED`: the value equals a declared dimension of compatible unit within that dimension's tolerance (`plate_t_mm 12.7` against the critical "plate thickness" 12.70 ±0.05; `n 8` against a circle of 8 holes whose Ø6.40 is a clearance for M6; `size #8-32` against a Ø3.45 hole, which is the 75 % tap drill 3.454 for #8-32).
   - `DERIVABLE`: an arithmetic combination of declared rows (`ri_mm 47.98` is the Ø95.96 groove-bottom bore over two; `t_mm 2.77` is (101.50 − 95.96)/2 between the shoulder OD and that bore; `plate_t_mm 3.2` is a shear-pin hole's span 74.65 → 71.45; `engagement_mm 10` is a tap-drill hole's span 2.7 → 12.7).
   - `UNWITNESSED`: nothing declared can see it. For `force_N`, `P_MPa`, `v_max_m_s`, `alt_m` and the strengths that is by nature; for a length it means every candidate missed, and the nearest one is named with its distance.
   - `POLICY`: `sf_min`, a declared acceptance threshold rather than a physical quantity; a retry can lower it with no geometric consequence, so it is listed and diffed, but not counted as an invented physical input.
   The file's **invention surface** is the list of unwitnessed inputs: the numbers a retry can change with no geometric consequence.
2. **Two files.** Given an attempt and its retry it strips every comment (SPEC, FLIGHT, KIND and NOTE text all live in comments and the model rewrites them on every retry), normalises whitespace and compares the code; matches loads rows by check and name and diffs every key; recomputes PartForge's contract floor (`flightCounts`); and flags `input_moved_geometry_unchanged` for each loads key that changed while the code is byte-identical, and `floor_loss` for any category that declares fewer entries. Declaration changes (a nominal, a station, a hole count) are listed as information, because the CMM re-measures those against the mesh.

A file with no `FLIGHT` block, with malformed JSON, or with no loads rows is a structured refusal (`not_found` / `invalid_input` / `insufficient_data`, a reason and what would help), never an empty table. "Witnessed" means a *declared* dimension matches: PartForge's CMM is what measures that declaration against a mesh, and nothing here measures a mesh. The tool names the row the app would measure. It cannot know that an unwitnessed number is wrong; it can only say that nothing checks it. It reports and never rewrites.

## Why I made it

**The open item.** PartForge's roadmap evaluation (`docs/roadmap-evaluation.md` at `0974a62`) names this twice as a structural hole:

- Wrong-number risk 9 (`:313`): "Every failing loads row lands in `g.fails` and is handed back to the model with 'correct the inputs if they were wrong.' For any input with no geometric shadow … the model's cheapest fix is to edit the number. **The geometry stays byte-identical and nothing detects it.**" The same sentence recurs in the guard for the bonded-joint idea (`:651`: "Nothing measures engage_mm … the geometry stays byte-identical and nothing detects it").
- Shared infrastructure **D** (`:131–133`), "Provenance that means something", first bullet: "**Measured-input cross-reference.** A join from a loads entry to the CMM-measured `od`/`bores`/`critical-extent` rows by name or station. It does not exist: the evaluator reads `l.ri_mm` and `l.t_mm` straight off the declaration." It is scheduled inside build-first item 3 (`:249`), and the completeness critic (`:351`) adds that "a first-class refusal state" is "assumed everywhere, specified nowhere".

The code agrees with the document. `parseFlight` (`index.html:4672`) copies every loads key off the declaration (`:4735`); the evaluator reads `l.P_MPa`, `l.ri_mm`, `l.t_mm` (`:5756–5757`), `l.root_mm … l.v_max_m_s` (`:5762–5767`), `l.engagement_mm` (`:5771–5773`), `l.force_N` (`:5781`) and `l.plate_t_mm` (`:5810`) directly; `row.provisional` (`:5820`) depends on `inputs_src`, not on anything measured; both retry hints say "correct the inputs if they were wrong" (`:5751`, `:5778`); the contract floor (`:5840–5843`, counts from `flightCounts` at `:4823`) forbids *fewer* entries but says nothing about changed values; `flightContradictions` (`:4847`) checks critical nominals against SPEC part sizes only. The headless `check` envelope prints the loads rows as `check, sf, sf_min, inputs, provisional` (`headless/partforge.mjs:103`), no shadow. `headless/llm.mjs design()` (`:141`) keeps the attempts of a run in memory (`:142`, returned in the envelope at `:185`) and `cli.mjs --out` writes only the chosen code, so nothing on disk compares attempt *n* with attempt *n* − 1. The six recorded Gemini flight rings (`docs/runs/2026-10-06-gemini-flight-x5/`) show the loop in action: every ring failed attempt 1 and passed attempt 2, and only the passing file was kept.

**Alternatives weighed.**

- *Witness against the mesh, not the declaration.* The honest ideal, and the app's own CMM already does half of it. It needs `openscad-wasm` (14 MB, not vendorable here, and neither OpenSCAD nor the wasm is installed in this sandbox) and would duplicate `measureExtent`/`measureBore`. Foundation D's own wording is a join "by name or station" to the rows the CMM measures, which is a declaration-level join; that is what this does, and the README says "declared" wherever it matters.
- *Patch PartForge's retry loop.* The right landing, not something a deposit may do, and the detection is more useful as a step a harness can call on any two files than as a line inside `design()`.
- *Per-input provenance* (D's second bullet: `inputs_src` is one field per row). A schema change for PartForge to make; the shadow table shows exactly which inputs such a field would have to cover.
- *A geometry digest from measured extents* (foundation H says a text hash of the `.scad` is the wrong record key because comments change on every retry). For a record store H is right. For attempt-versus-retry the question is literally "is the code outside comments byte-identical", so a comment-stripped text comparison is the correct instrument here, and it is what the evaluation's sentence asks for.

This won because it is the smallest thing that answers the evaluation's sentence and refuses when it cannot.

## How it works

**Fixtures.** Fourteen `.scad` files copied from the PartForge checkout at `0974a62` with `tools/snapshot.mjs` (sidecars under `snapshots/`; every copy's read blob matched the committed blob): six of the seven shipped templates in `tests/templates/` (`av-sled`, `bulkhead`, `centering-ring`, `coupler`, `fin`, `motor-retainer`; `nosecone` carries `loads: []` and would only repeat the av-sled refusal), the three dry-run cases in `tests/dryrun/` (`endcap`, `retainer`, `retainer-fixed`, the last "hand-corrected from retainer.scad" per `cases.json`), four of the six recorded Gemini rings (`ring1`, `ring3`, `ring4`, `ring6-after-doctrine-fix`; rings 2 and 5 repeat ring 1's shape of declaration), and one derived file, `motor-retainer.retry.scad`: the template with exactly one edit inside the FLIGHT block, `"force_N":20000` → `"force_N":12000`, and code outside comments byte-identical (`build-data.mjs` asserts both; a test re-checks).

**Parser.** `shadow.js` parses the FLIGHT block the way `index.html` `parseFlight()` (`:4672–4751`) does, field for field: strip `// ` from the block, `JSON.parse`, cap each category at 24 entries, drop a critical without an axis or a positive nominal and tolerance, drop a round feature whose `from_mm` equals `to_mm`, default `pos_tol_mm` to `tol_mm`, keep a loads row only for `hoop|flutter|thread|bolt_shear`, copy its keys through `/^[a-z_]+$/i` (numbers stay numbers, everything else becomes a string cut to 40 characters), normalise `inputs_src` and demote a `source` claim without an `inputs_ref` to `default`. `build-data.mjs` cuts PartForge's own parser out of `index.html` between its anchors (the same marker extraction `tests/run.mjs` uses) into `snapshots/flight-decl.js`, and a test runs both parsers over every fixture and a set of edge cases and demands identical output on every field the evaluator reads, plus identical `flightCounts`.

**Candidates** from a parsed declaration (all mm):

| candidate | from | value | tolerance |
|---|---|---|---|
| extent | each `critical` row | `nominal_mm` | its `tol_mm` |
| span | each `od`, `bores`, `holes` row | \|`from_mm` − `to_mm`\| | its `tol_mm` |
| wall | each `od` × `bores` pair on the same axis and `at_mm`, with `od.d > bore.d`, whose axial ranges overlap | (`od.d_mm` − `bore.d_mm`)/2 | mean of the two `tol_mm` |
| radius | each `bores` row | `d_mm`/2 | `tol_mm`/2 |
| count | each `holes` row | circle `n`, list length, or 1 | exact |

The overlap condition matters: on the endcap the flange OD (z 0–5.4) and the O-ring groove bore (z 11.15–15.9) are coaxial but share no stretch of axis, so no wall is formed from them; the shoulder OD (5.4–25.4) and that bore do, and that wall is the 2.77 mm the hoop row declares.

**Rules**, by the meaning each key has to the evaluator (`index.html:5754–5813`):

| input | kind | witnessed by | derivable from |
|---|---|---|---|
| `plate_t_mm`, `thick_mm`, `t_mm` | thickness | an extent within tolerance | a wall or a span within tolerance |
| `root_mm`, `tip_mm`, `span_mm`, `sweep_mm` | planform | an extent | — |
| `ri_mm` | radius | — | a bore's `d_mm`/2 |
| `engagement_mm` | engagement | — | a hole or bore span, preferring a row whose diameter is a tap drill for `size` (else the note says it may be a clearance hole and the tapped part the mating one) |
| `n` | count | a hole row with that count **and** a diameter that is a clearance for `size` | — (a count-only match with the wrong diameter stays unwitnessed and says so; an unknown size falls back to count only) |
| `size` (a string) | thread | bolt_shear: a hole row at a clearance diameter for the size; thread: a hole or bore at a tap-drill diameter | — |
| `force_N`, `P_MPa`, `v_max_m_s`, `alt_m`, `bolt_sigma_y_MPa`, `bolt_sigma_u_MPa` | no shadow | — | — |
| `sf_min` | policy | — | — (the doctrine default 2.0 / 1.5 / 2.0 for hoop / flutter / bolt_shear is noted, from `:5759`, `:5767`, `:5812`) |
| any other numeric key | unknown | — | — (unwitnessed; PartForge's check does not read it) |

A length matches when |value − candidate| ≤ tolerance (+10⁻⁹). "Clearance for a size" means the hole diameter lies between the thread's major diameter and its loosest clearance, each widened by the hole's tolerance; "tap drill" means within the hole's tolerance of a tap-drill diameter. Those diameters come from `snapshots/fasteners_metric.excerpt.js` (all 12 rows of `data/tables/fasteners_metric.json`: `d_mm`, `tap_drill_mm`, `tap_drill_stainless_mm`, the three ISO 273 clearances) and `fasteners_un.excerpt.js` (all 16 rows of `fasteners_un.json`: `major_mm`, the 75 % and 50 % tap drills, the three B18.2.8 clearances). Every row keeps its `confidence` and the witness text prints it: four UN rows are `recall` (`#2-56`, `#12-24`, `1/2-13`, `1/2-20`), the fixtures touch only `#2-56`, and the coupler's witness says `(fasteners_un recall)`. The excerpts carry the tables' `license_note`, and the per-row `source` text, identical across all 12 metric rows and 15 of the 16 UN rows, is kept once as `rows_source` (the one UN row that differs keeps its own). When a bolt_shear row names a `motor`, the note adds what the evaluator would do (`:5786–5793`): hold `force_N` to the certified peak in `motor_perf.json`. `snapshots/motor_perf.excerpt.js` holds the one row the fixtures name, Loki L2050 (`max_thrust_N` 3331, `max_thrust_src` "certified", confidence `likely`), matched as `dbMotorPerf` matches (`:4907–4916`); the note calls that a data witness, not a geometric one, and says whether the declared value equals the peak. A motor outside the excerpt is reported as not in the excerpt.

**The two-file diff.** `geometryText()` removes `/* … */` blocks and `//` comments, trims and collapses whitespace per line and drops blank lines; the two texts are compared for identity and, when they differ, an LCS over lines gives removed/added counts. Loads rows are matched by (`check`, `name`); every key of the union is compared (numbers to 10⁻⁹, strings exactly), and each changed key is reported with its class before and after. Declaration rows are matched by name and their nominal, diameter, tolerance, stations, count and bolt circle compared. The floor is `flightCounts` before and after, with lost categories named exactly as `index.html:5840–5843` would fail them. Findings: `floor_loss` per lost category; and, only when the geometry text is identical, `input_moved_geometry_unchanged` per changed loads key, worded by what the input was (an unwitnessed input; a witnessed input, "and it lost its witness"; the acceptance threshold; a declared key such as `grade`, `motor` or `inputs_src`). A moved input with changed geometry is listed, not flagged: that is an ordinary retry.

**Exit codes and the envelope.** As `headless/cli.mjs`: 0 / 1 / 2 / 3. One file never exits 1: its table is information. `--json` wraps the result as `{ ok, tool, value, units, confidence: 'measured', provenance, assumptions, validity_envelope, summary, refusal? }` (`headless/partforge.mjs:41`), with the three excerpts' repo, path and commit in `provenance`; `confidence: 'measured'` means read from the declaration text, and the assumptions say so.

**What the fixtures show** (`findings.js`, recomputed by a test; the page renders it):

## Honest assessment

- **[Certain] The classification is exactly what the rules table says, over the declaration PartForge's own parser produces.** The parser agreement test runs PartForge's `parseFlight` beside this one on every fixture; the witnesses quote the rows and the arithmetic; every fixture number in this README is produced by the tests.
- **[Certain] Nothing here measures a mesh.** `WITNESSED` means a declared dimension matches. The CMM's job (does the mesh have that dimension) is PartForge's, and the app's own tests say the seven templates pass it. A declaration that is itself wrong (a critical nominal that does not match the part) would witness a loads input just as well; the join is only as good as the declaration the CMM will then check.
- **[Certain] The tool cannot tell an invented number from a right one.** `force_N 20000` on the motor retainer is the doctrine's own illustrative default (the evaluation's foundation B says so); `force_N 3331` on the rings is a certified peak the app itself verified against its table. Both are `UNWITNESSED`, because that is a statement about geometry, not about truth. The motor note is the one place the tool reaches for data, and it says "a data witness, not a geometric one".
- **[Certain] The synthetic retry is synthetic.** `motor-retainer.retry.scad` was made by this folder's `build-data.mjs`, and the README says so wherever it appears. No recorded PartForge run keeps a failing attempt beside its passing one (`design()` keeps attempts in memory), so there is no real attempt pair in the checkout; the real pair here, retainer → retainer-fixed, is a hand correction, and the differ reports it as a geometry change with unchanged inputs, which is what it is.
- **[Likely] The rules are the right first set.** Unit-compatible pairs only, within the declared tolerances, with walls requiring axial overlap and counts requiring a size-compatible diameter: on the fixtures this produced no witness I could not defend and no coincidental match (the bulkhead's 8 bolts never meet its 12.7 mm plate; the ring's four lightening holes never witness its four M4 bolts). Whether that holds on files from other models is untested here.
- **[Likely] A moved input with byte-identical geometry is the signal worth failing a retry on.** The evaluation says so and the fixtures' retry history (six of six first attempts failed on inputs or a declaration, not on the mesh) is consistent with it. A model that rewrites one comment or re-indents the code defeats the byte-identity test trivially; the comment stripping and whitespace normalisation cover the common cases, a semantic equivalence of OpenSCAD code they do not.
- **[Speculative] What a maintainer would do with the invention surface.** My guess is that it becomes a line on the manufacturing sheet ("3 of 8 check inputs are declared, not measured") and a reason to require `inputs_ref` for them. That is a design question for PartForge, not something this tool settles.
- **Rough.** Station arithmetic across two features (the endcap's 25.4 − 8.0 = 17.4 face plate) is deliberately not a rule, because pairwise station differences across ten features produce too many coincidences; the fixture that needs it comes out unwitnessed with the nearest candidate named. Comment stripping assumes `//` and `/* */` never occur inside OpenSCAD string literals. Loads rows are matched by check and name, so a retry that renames a row shows as one row removed and one added. The line diff is an LCS count, not a readable diff. The browser page cannot read the `.scad` snapshots from `file://`, so its "load sample" fills in a minimal declaration rather than the real file. The PartForge vocabulary (`certain / likely / recall`) is printed on witnesses from the tables; the bank's `[Certain]/[Likely]/[Speculative]` is used only in this README.
- **Fidelity.** An idea-bank prototype. It has not been through PartForge's geometry gate (no file here was compiled or CMM-measured in this sandbox), its data-provenance pipeline (`tools/db/`, `tests/flight-db*.test.mjs`) or a skeptic review, and it is not wired into the retry loop or the doctrine.

**Findings about the source repo** (PartForge at `0974a62`; observed, not fixed there):

- **F1. `threads_in_shear:false` can never be honoured.** The loads key copier (`index.html:4735`) turns every non-number into a string, so a declared boolean arrives as the string `"false"`, and the bolt-shear branch's `l.threads_in_shear === false` (`:5809`) is unreachable; only `shear_plane:"shank"` works. The doctrine (`:1461`) documents `shear_plane` only, so this is dead code rather than a wrong number, but a model that writes the boolean gets threads-in-shear silently. Pinned by the parser-agreement test against the extracted `parseFlight`.
- **F2. All six recorded Gemini rings lose their load provenance in the parser.** Each ring's bolt_shear row declares `"inputs_src":"source"` with `"motor":"Loki L2050"` and no `inputs_ref`; `parseFlight` demotes it to `default` (`:4738–4740`, `demoted: 1`), so the row is `provisional` (`:5820`) and reports COMPUTED rather than PASS, although the evaluator itself verified `force_N` against the certified peak (`:5786–5793`). The runs' README says, correctly, that "every external number came from the data PartForge supplied"; the app's own provenance field does not record it, because the `motor` key is not accepted as a reference. Pinned by a test on ring1/3/4/6 through both parsers.
- **F3. The contract floor counts declarations, not what they measure.** `tests/dryrun/retainer-fixed.scad`, the hand-corrected version of `retainer.scad`, declares `od` 2 → 1 (two OD sections merged into one) and `gauges` 0 → 2. Had that correction arrived as a retry, `:5840–5843` would have failed it with "declares fewer FLIGHT entries than the previous version: od 2 → 1". The floor forbids fewer entries per category; a retry may also change any value or station freely. An observation about the mechanism, pinned by the real-pair test.
- **F4. The coupler template's `n 3` has one witness per end.** `tests/templates/coupler.scad` declares a single shear-pin hole at 0° at each end and proves the 120°/240° pins with a gauge module (`gauge_pins_go`), so the bolt-shear row's three pins are not a hole row anywhere; the check divides 150 N over 3 pins that the declaration cannot count. Not a wrong number; a gap between what the gate measures and what the check assumes.
- **F5. Stale line references in `docs/roadmap-evaluation.md`.** `:246` and `:280` cite `GRADE_SY` at `index.html:4929` (it is at `:5804`, and the SAE grade-2 entry `'2':393` the evaluation calls missing is now present, so wrong-number risk 1 is resolved at this commit); `:129` and `:567` cite the ok-guard at `:4939` (now `:5817`); `:651` cites `row.provisional` at `~4823` (now `:5820`; `:4823` is `flightCounts`). The proposal for this idea inherited two small offsets of its own (the key copier is `:4735`, not `:4733`; the hoop branch that reads `l.ri_mm`/`l.t_mm` is `:5756–5757`, before the `:5779` bolt-shear range it cited).

**Deviations from the judged proposal, and why.**

- A fourth class, `POLICY`, for `sf_min`. Lowering the threshold is the cheapest fix of all and must be diffed; counting it as an invented *physical* input would overstate the invention surface. The proposal's three classes cover everything else.
- `size` (a string) is classified, through excerpts of the two fastener tables. The proposal said "no tables"; without them `n 2` on the bulkhead would have matched three hole rows with two positions each, and nothing could name the right one. The excerpts keep `confidence` and the `recall` row is printed as recall.
- Walls require axial overlap; the proposal's "(od − bore)/2" would have produced a 15.5 mm "wall" between the endcap's flange and a groove 6 mm above it.
- The diff flags every changed loads key, not only numeric inputs: `grade`, `motor`, `inputs_src`/`inputs_ref` and `sf_min` are all cheap fixes.
- One-file mode is informational (exit 0); the proposal's "exit 0/1/2" is kept with 1 reserved for pair-mode findings. The count mismatch the proposal wanted "reported" is reported inside the `n` row (unwitnessed, with the clearance-size rows named), not as a separate finding.
- Fixtures: nosecone dropped (no loads rows), `retainer.scad` added (the only real before/after pair), rings 2 and 5 dropped, ring 6 added (the first first-attempt pass); the motor row and the fastener excerpts added.
- The evaluator citation is `:5745–5828` with the per-check lines given above; the proposal's `:5779–5845` starts at the bolt-shear branch.

## Where it would land

**PartForge**, in three places:

1. `headless/cli.mjs` and `headless/mcp.mjs`: a `shadow <part.scad> [retry.scad]` command beside `check`, built on `core.gen.mjs`'s own `parseFlight`, `flightCounts` and `FLIGHT_DB_DATA` (`dbMotorPerf`, the fastener rows) instead of this folder's excerpts, returning the same envelope shape. `shadow.js` is the logic; its parser would be deleted in favour of the generated one, and the parser-agreement test becomes unnecessary.
2. `headless/llm.mjs design()` (`:141`): after each `check()` of attempt *n* ≥ 2, diff against attempt *n* − 1 and treat `input_moved_geometry_unchanged` as a failure fed back through the retry message, next to the existing "declares less than your first one" clause; in the browser, the same at `index.html:7638` where `contractFloor` is set. That is the detection the evaluation says does not exist.
3. The evaluator's loads loop (`index.html:5745`): a `row.witness` (class and witness text per input) rendered in `mfgSheet()`/`icdSheet()` and in `headless/partforge.mjs measurementRows()`, so the sheet says which check inputs the geometry vouches for. Tests under `tests/` next to `flight-decl.test.mjs`, with the seven templates as cases.

What must change to ship: foundation D's per-input provenance (`inputs_src` per key, or an `inputs_ref` that `motor` can satisfy, F2); a doctrine line telling the model what a witness is and that an input it cannot witness must be cited (the "doctrine tax" the evaluation prices at two days); a decision on the floor's semantics (F3); and PartForge's own gates, since none of this has been through its geometry gate, data pipeline or skeptic review.
