## What it is

Skyhook's Rule 1 is that every tether number comes from `params/rev_a.json`, never from memory, and the program's own handoff records two errors that came from breaking it. Nothing in the repository enforces the rule on the places where numbers actually get written: the founding document, the glossary, the FAQ, the program site's HTML, the React simulators, the finance notes. `lint_canon.py` walks a checkout and does three things:

1. **Quantity rules.** Every number that carries a unit (GPa, kg/m³, km/s, km, g, min, km²/s², ×, $/kg, $M, t) is attributed to the nearest keyword on its line, counted in tokens. If that keyword names a canonical quantity ("SK99", "mass ratio", "apogee", "lower tip", "Falcon 9" …) the number is compared, rounding-aware, with the `rev_a.json` keys the rule lists; if it names a quantity the repository legitimately states that is not canon (payload, Δv, exhaust velocity, perigee, prices, moduli: the *sinks*) the number is left alone. Assignments in code (`VTIP=3.5`, `sigma: 3.9e9`, `L=320`) are attributed directly.
2. **Stale patterns.** "3.5 km/s" with no Phase-3 label within reach; "440×" with no unsourced/historical label; "100–200×" in any spelling; a Conservative / Baseline / Optimistic ladder whose derate or retention rungs are not the tier's own `rev_a.json` value.
3. **Schema drift.** Parameter paths in code (`revA.a.b`, `PARAMS["a"]["b"]`, `["a", "b"]` pairs) and dotted keys quoted in prose after "rev_a.json" are resolved against the JSON. A path that does not exist is reported together with the keys that do.

Each hit is classed from the deviations register: **ACCEPTED** (the register's disposition says *Leave*: a deviation that states itself), **KNOWN OPEN** (tracked, not marked EXECUTED), **NEW** (untracked, or in a row marked EXECUTED, which is a regression), and **LABELLED** (a quantity mismatch whose wide window carries a self-label such as *Phase 3*, *growth option*, *historical*, *superseded*, *was*, *HASTOL*, *SF 5*; shown, never failing). Only NEW sets the exit code. `--cite <key>` prints the value, the notes beside it in the file, their confidence labels, the file, its commit and its sha256, as a Markdown quote. `--verify-canon` recomputes every derived value in `rev_a.json` from the file's own inputs.

## Why I made it

The open items this serves, with where they are written down:

- `handoff.md:21` "Two errors found & fixed this session (both from quoting canon by memory)" and `handoff.md:24` "Lesson: tether numbers come from `params/rev_a.json`, never from memory"; `handoff.md:35` open item 6, the founding-doc worked example and teaser/deck/FAQ "still carry old canon".
- `docs/DEVIATIONS.md:14` item 8: "Align to rev_a.json's canonical factors (0.70 / 0.85 / 1.00) in a future calculator pass. Not fixed here." The register is kept by hand; nothing re-checks it.
- `CLAUDE.md:20` rule 2, "Never hardcode a physics parameter", which the two `.jsx` simulators break in opposite ways: one hardcodes, one imports a key that is not there.
- The bank's `BRIEFING.md` §4: "Linting tools that catch canon drift, literal labels and provenance gaps are wanted everywhere and exist nowhere."

What already exists, and why it is not this: `tests/test_rev_a_physics.py` checks `rev_a.json` against the physics module; `tests/test_finance.py` checks the workbook's derate ladder against it; `tests/test_export_grid.py` checks the grid's provenance hashes; `tools/twin/params-loader.js` validates eight required keys at runtime, for the twin only. None of them read prose, HTML or JSX, and none resolve a JavaScript property path against the JSON, which is exactly how the stress-test simulator's bug lives on in a repository whose CI is green.

Alternatives I weighed. (a) A pure regex grep for the known stale strings (3.9, 0.72, 440, 100–200): catches today's five, nothing tomorrow, and cannot say *why* a number is wrong. (b) A JSON-schema contract for `rev_a.json` consumers: catches the missing key, says nothing about prose, and the repository has one Python and three JavaScript consumers with no shared schema. (c) Hand-maintaining `DEVIATIONS.md` better: that is the current state, and item 8 has been "not fixed here" since 2026-07-06. (d) This: a rule table keyed to `rev_a.json`'s own keys, with the register as the allow-list, so the maintainer's existing habit (write a row) is what silences a finding. The quote card is the other half: a finding tells you a number is wrong; the card gives you the right one with its provenance so you do not retype it.

## How it works

**The canon.** `rev_a.json` is flattened to dotted paths (`materials.alternative_fibers.Dyneema_SK99_GPa`, list items as `[i]`); numeric leaves whose names do not start with `_` are the checkable values (66 of them, `--list-keys`). Units come from the key suffixes the file already uses (`_kms`, `_km`, `_GPa`, `_kgm3`, `_g`, `_min`, `_kms2`, `_kgs`, `_M`, `_t`). Allowed values that are not keys are derived in the open and named as such in the report: total length 2L = 640 km, the inertial lower-tip speed `v_orb_kms − v_tip_kms` = 5.05 and `v_upper_release_kms − 2 v_tip` = 5.06 (both, because the file supports both; see the self-check), the retention `1 − derate` for each rung, and the per-tier rungs read off the key names `conservative_30pct_derate`, `baseline_15pct_derate`, `optimistic_0pct_derate`.

**Rounding rule** [Certain, `rounds_to`]. A literal matches canon when canon rounded to the lesser of the two precisions equals it: 122×, 121.8×, 121.83× and 121.826× all match 121.83; 85,200 km matches 85,222 because an integer ending in zeros is read at the precision of its last non-zero digit. Two caps keep this honest: the tolerance may never exceed 5 % of canon (so "SF 3" is not 2.5, "41×" is not 40.32, "10.05" is not 10.06), and the trailing-zero rule may never hide more than 3 % (so "600 km" is not 640, but "~600 t" is 609.1 and "~3,000×" is 3085.95). Fraction rules read a round rung at two decimals so 0.4 is not a derate of 0. A range (40–122×, 2.7–2.8 km/s, $10–30M) passes when it brackets a canonical value. A number preceded by a comparison (≤, <, below, at most, up to…) is a bound, not a claim; a number whose gap to its keyword holds an operator, an `@`, or another number with words around it (`v_orb + v_tip ≈ 10.06`, `fiber @ 5 t`, `sits at 0.92 V_c`) is an expression, not the quantity; a bare value list (`~41× (65×/123×`) is not.

**Attribution** [Likely]. For each unit-bearing number the scanner looks 100 characters back and 80 forward on the same line for every rule keyword and every sink, measures the distance in whitespace tokens, and gives the number to the nearest one (ties to the keyword before the number, then to the rule stated in the number's unit; a keyword more than 8 tokens away does not count; a keyword that is itself an operand, `v_orb − v_tip`, does not count). If the winner is a sink, or is a rule stated in a different unit, nothing is checked. The window for *labels* is wider: 200 characters back and 120 forward, spilling into the neighbouring lines, plus the nearest Markdown heading, so a number under "### Phase 3" inherits the label.

**Classes** [Certain for the matching, Likely for the keywords]. `DEVIATIONS.md` is parsed by its table rows: the backticked paths in the location column, the `"…"` and `` `…` `` snippets that carry a number (an elided tail is kept as a prefix, so "meet our launch vehicle at, say, 3.5 km/s slower…" still matches), the numbers named, and the disposition: a row with *Leave* is ACCEPTED, a row with EXECUTED is fixed (a finding that still matches its snippet is a regression and goes back to NEW with a note), anything else is KNOWN OPEN. A row with snippets matches a finding by snippet on the finding's line; a row without (item 8 quotes `{d:.6,...}` with an ellipsis) matches by value. Files that declare, near the top, that they run on `params/service_mxer_draft.json` (the DRAFT in-space set) are scanned for patterns and schema only and named in the report header; `params/rev_a.json`, `docs/DEVIATIONS.md` and `docs/verification_memo.md` are skipped because quoting the wrong numbers is their job.

**Quote card.** For a key, the notes in the same object whose name shares a token with the key or whose text mentions its stem (`v_tip_kms` gets `_lower_tip_note` and `_tip_accel_note`), their `[Certain]/[Likely]/[Speculative]` or "; Certain" labels, and the provenance: the snapshot's sidecar commit and sha256 when the file is a snapshot, else the checkout's HEAD if git tracks the file. A snapshot never borrows the commit of the repository it was copied into.

**Canon self-check** [Certain]. `--verify-canon` recomputes V_c = √(2σ/ρ), v_orb, release and catch speeds, tip g, rotation period, C3 and apogee at the upper-tip radius, the five mass ratios by EQ-6 (Moravec/Forward, `2√π·x·eˣ²·erf(x)`, `x = (V_t/V_c)√(SF/(1−derate))`, with `math.erf`) and the five fiber masses, from the file's own σ, ρ, SF, tip speeds, altitude and half-length. Constants not in the file are declared: R_E 6371 km as `physics/skyhook_physics.py:40`, the sidereal day 86164.0905 s (which gives the 0.465 km/s equatorial speed the notes use), g₀ 9.80665 m/s². 23 of 26 values reproduce, including all five ratios to two decimals with the *exact* V_c (2.7269 km/s; the rounded 2.73 gives 120.84, not 121.83). Three do not; they are findings about the source repo below.

**Data.** `snapshots/rev_a.json` and `snapshots/DEVIATIONS.md` are whole copies made with the bank's `snapshot.mjs`, as are two fixtures (`skyhook_calculator.jsx`, `glossary.md`). The other seven fixtures under `snapshots/fixtures/` are excerpts derived by `build_data.py`: the listed line ranges are copied verbatim and every other line is left empty, so a finding at `snapshots/fixtures/tools/sims/skyhook_program_site.html:1135` is the repository's own `file:line`; each carries a `--sidecar-only` provenance sidecar naming the ranges and the commit. `example.txt` is the live run against `/home/user/skyhook`; `page-data.js` is the same run written by `--emit-page-data` for the page, which computes nothing itself.
