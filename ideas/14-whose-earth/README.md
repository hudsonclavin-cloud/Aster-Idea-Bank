# Whose Earth
> Every line in Aster and Skyhook that states Earth's μ, radius, g0, rotation speed or a reboost energy per kilogram (94 cited lines, re-verified against both checkouts on each run): Aster computes on μ 398,600.4418 km³/s² and R 6,378.137 km, Skyhook on 398,600 and 6,371, which at the K2 interface moves the tether's release C3 by +0.021 to +0.029 km²/s² (+0.107 if one side's speed meets the other's radius) and the cislunar apogee by +5,730 km, while the μ difference alone moves C3 by 0.00004. ## What it is

A concordance and a study. When Aster hands a payload to a Skyhook tether (the K2 interface), the two programs compute speeds and energies about the same planet with different numbers for it. This deposit:

1. **Lists every place either repository states an Earth constant.** `registry.js` holds 94 rows: file, line, the exact text that must be on that line, the literal, its unit, what kind of statement it is (a code literal, a comment, prose, a radius from which an Earth radius follows, a formula) and where it lives (canon, code, page or simulator, test, docs, research record, vendored kernel). Five quantities: the gravitational parameter μ, the Earth radius, standard gravity g0, the equatorial rotation speed, and the reboost energy per kilogram thrown (mechanical in MJ/kg, electrical placeholders in kWh/kg). On every live run the CLI re-reads each row's line in the checkout (a row that moved, vanished or became ambiguous fails the run) and scans both repositories for any occurrence of these constants the registry does not list (an unlisted occurrence fails the run too), so the table cannot quietly rot.
2. **Builds each program's Earth from those rows** and recomputes every number in Skyhook's `params/rev_a.json` that follows from the file's own inputs, on each Earth, against the rounding the file prints.
3. **Sizes each difference at the interface**: the tether's release C3 split into what μ does, what the radius does and what mixing does; apogee; v∞* = √C3; Tip Match's trim; and Aster's own injection Δv to the same C3.
4. **Reconciles reboost energy**: four accountings of the energy one throw costs the tether, the figures the Skyhook repository states and computes, a 144-reading sweep for MP-001's 44.8 MJ/kg, and the decision grid's published reboost line reproduced to four decimals.
5. **Refuses where a constant is missing.** Aster's `src/v2` states no Earth rotation rate, so the lower-tip ground-relative speed on Aster's Earth is a structured refusal with what would help, never a borrowed number; the canon's GTO and TLI threshold speeds need a target radius `rev_a.json` does not state and are refused on every Earth.

## Why I made it

**The open items.** K2 is Aster's CONCEPT kernel for the Aster → Skyhook interface (`strategy/IDEA_KERNELS_2026-09.md:35`, §1 row 16: "Tether constants come ONLY from Skyhook `params/rev_a.json`, never from memory"), carried as the L9 Aster Momentum lens (`strategy/ASTER_FAMILY_MASTER_PLAN.md:41`). An interface needs one Earth, and nothing in either repository says which. Aster's INV-026 (`INVARIANTS.md:200`) says every numeric claim on a trust surface renders from a committed provenance artifact, never from literals in component code. Skyhook's `CLAUDE.md:20` (rule 2, "Never hardcode a physics parameter") and `:23` (rule 5, "No magic numbers") are broken by its own physics module, which hard-codes the radius and rotation speed because `rev_a.json` has no key to import (`physics/skyhook_physics.py:40, :109`). The bank's `BRIEFING.md` §4 names the seam first.

**What earlier deposits found, and what is new here.** Idea 01 (Tip Match, F1) and idea 04 (Rule One, finding 8) found that `rev_a.json` carries two Earth radii; idea 01 measured the reference-tier C3 shift (0.029 consistent, 0.106 mixed); idea 09 (Two Seconds at the Bottom, F4) found the 0.465 rotation literal. I cite those rather than rediscover them, and a test reproduces idea 01's numbers. What none of them does: put Aster's constants beside Skyhook's, line by line and kept current by a scan; decompose the interface effect into μ, radius and mixing for every tier and carry it into apogee, v∞*, trim and Aster's own injection function; or reconcile Skyhook's reboost energy, which three documents in the repository state three ways.

**Alternatives weighed.**
- *A table in a README.* Cheapest, and it would be stale the first time either repository moved a line. Rejected for a registry that a run re-verifies, plus a scan that fails on anything unlisted.
- *Extend Rule One (idea 04).* It lints Skyhook prose and code against `rev_a.json`. This question spans both repositories and needs physics (what a radius does to C3), so it is its own tool; it uses the same snapshot discipline.
- *Declare the right Earth.* Rejected. The WGS84 equatorial radius (Aster) and the mean radius (Skyhook) are both legitimate conventions; the honest output is the size of the difference and where it matters, and a recommendation that the interface record one.
- *A full K2 envelope.* Tip Match (idea 01) already builds one; K1 (the return leg) does not exist yet. This deposit supplies the constants such an envelope would declare in its `assumptions`.

## How it works

**The registry and its verification.** Each row is `E(id, family, repo, path, line, token, literal, unit, role, kind, note)` in `registry.js`. `collect.mjs` reads the file, checks the token is on the stated line and the literal is inside the token, and reports `ok`, `moved` (found once elsewhere), `ambiguous`, `missing` or `no-file`. A row's value is the literal converted to the family's unit (`model.parseLiteral` reads `398_600.4418`, `6,378,137`, `6371e3`, `3.986 × 10¹⁴`; division for SI-to-km so `3.986004418e14 / 1e9` is exactly 398,600.4418). Three kinds turn into an Earth radius: Aster's parking radius minus the parking altitude its page discloses (`implied-parking`, paired with the altitude row); `rev_a.json`'s `com_radius_km` minus `com_altitude_km` (`implied-com`, 6,988 − 610 = 6,378); its "r_tip = 7301 km" notes minus 610 and 320 (`implied-tip`, 6,371).

**The scan.** `git ls-files` in each checkout, every text file under 2 MB, five regular expressions (`registry.js` `SCAN`): μ (`398600…`, `3.986…e14`, `3.986 × 10¹⁴`), radius (`637[18]…`, `6578.137`), g0 (`9.80665`, `9.81`), rotation (`0.46`, `0.465`, `V_EQ = 465`, `465 m`, `7.292…`, only on a line that also says rotat/equat/v_earth/VEQ), and energy (`… MJ/kg`, `… kWh/kg`, the two code spellings, only on a line about reboost or orbital energy). A hit whose file, line and family no row covers is UNREGISTERED. Out of scope, each with its reason in `registry.js`: Aster's `docs/` (deployed build output, `AGENTS.md:31`), its legacy V1 code (`tsconfig.json:21-35`, `AGENTS.md:37-38`; scanned and summarised by value, not listed: 9 files with 5 occurrences of μ 398,600, 8 of 398,600.4418, 7 of R 6,371 and 4 of g0 9.80665), `_rescued-agent-defs/`, `tests/fixtures/`, the sealed `tools/slice16-harness/`, and JSON data in both repositories except Skyhook's `params/`. At the commits read: Aster 566 files scanned, 36 lines with a candidate; Skyhook 73 files, 45 lines; 0 unregistered. The registry was built from that scan by hand; false positives were removed by scoping, not by listing.

**The Earths** (`registry.js` `EARTH_SETS`, values from rows, never typed): *Skyhook physics module* = μ `rev_a.json:11`, R `skyhook_physics.py:40`, g0 `:41`, rotation `:109`. *Aster v2 porkchop* = μ `delta-v.ts:3`, R `delta-v.ts:4` − `main.ts:981`, g0 `launch-vehicles.ts:63`, rotation none. *rev_a.json orbital block* = the Skyhook set with R from `rev_a.json:10`.

**The canon, recomputed** (`model.deriveCanon`, mirroring `physics/skyhook_physics.py`): r_com = R + 610, r_tip = r_com + 320, r_low = r_com − 320 (km); v_orb = √(μ/r_com) (EQ-2); release v_orb + v_tip, C3 = v_rel² − 2μ/r_tip, apogee 2(−μ/C3) − r_tip − R (EQ-3b, EQ-7, `:113-166`); lower tip v_orb − v_tip − v_rot (EQ-3a); tip acceleration v_tip²/L/g0; rotation period 2πL/v_tip; V_c = √(2σ/ρ) (EQ-4); EQ-6 mass ratio 2·√π·x·e^(x²)·erf(x) with x = (v_tip/V_c)·√(SF/(1 − derate)) (`:219-241`, Moravec/Forward as the module names it), with erf from the all-positive series 2/√π·e^(−x²)·Σ 2ⁿx^(2n+1)/(2n+1)!! (no cancellation; JavaScript has no erf); the C3 = 0, 8 and 13 tip speeds √(C3 + 2μ/r_tip) − v_orb. A value "reproduces" if it rounds to the printed number at the printed number's own decimals. Results: on the Skyhook Earth 15 of 18 checkable Earth-dependent values reproduce, and the three that do not (`com_radius_km` 6,988 vs 6,981, `v_orb_kms` 7.55 vs 7.5563, Phase 3 `v_upper_release_kms` 11.05 vs 11.0563) are exactly the ones on the 6,378 km Earth; on Aster's Earth 9 of 16 reproduce (the two lower-tip speeds refuse) and the seven kinematic values miss (reference and cislunar release speed, C3 and apogee, Phase 3 C3); the orbital-block Earth misses the same seven. All 19 Earth-independent values (V_c 2.73, σ/ρ 3.72, the five mass ratios 40.32 / 64.30 / 121.83 / 295.27 / 3,085.95 and their fiber masses, rotation period 13.4 min, …) reproduce and are identical on every Earth: the Earth choice cannot touch the numbers Skyhook's economics hang on.

**The interface** (`model.c3Shift`, `interfaceEffects`): from the Skyhook Earth to Aster's, ΔC3 = +0.0290, +0.0267, +0.0213 km²/s² for the 2.5, 2.8 and 3.5 km/s tiers; μ alone −0.000037 / −0.000034 / −0.000028 (first order: (v_rel·v_orb/μ − 2/r_tip)·Δμ); the radius alone +0.0290 / +0.0267 / +0.0213; mixed (v_orb from one Earth, r_tip from the other) +0.1066 for every tier, which is 2μ(1/r_tip − 1/r_tip′) exactly. Apogee: reference 85,222 → 85,565 km (+343, +0.40 %), cislunar 397,819 → 403,550 km (+5,730, +1.44 %; +23,961 mixed), the most Earth-sensitive number in the canon. v∞* for Phase 3: 3.6127 → 3.6156 km/s (+2.9 m/s). Tip Match's trim at v∞ = 0: 0.3931 → 0.3919, 0.0931 → 0.0919, −0.6069 → −0.6081 km/s. Aster's own injection Δv to each tier's C3 from its 200 km parking orbit (`delta-v.ts:18-26`, ported, not modified): 2.8539 → 2.8533, 3.1378 → 3.1372, 3.8034 → 3.8029 km/s, −0.5 to −0.6 m/s. Earth rotation enters none of these: K2 is an inertial energy question.

**Aster's own pins.** The CLI parses four worked injection values from the verified line text of Aster's Slice 11 founding record (`src/v2/SLICE_11_FOUNDING.md:452`: C3 1,781.29 → 35.83, 8.78 → 3.616, 32.16 → 4.599 km/s) and its audit (`tools/audit/sanity-69472a3/s19-5-runs/verify-REPORT.md:96`: C3 0 → 3.224 km/s). All four reproduce with Aster's constants; three of four miss on Skyhook's Earth (3.6177, 4.6003, 3.2261), so Aster's published numbers are visibly on its own Earth at four significant figures.

**Reboost energy** (`model.reboost`; km²/s² = MJ/kg). In Skyhook's kinematics the payload is caught at r_low moving v_orb − v_tip and released at r_tip moving v_orb + v_tip.
- *Momentum view*, the finance model's line (`finance/skyhook_finance.py:211-216`, "workbook EQ-5 momentum view"): 2·v_orb·v_tip = 37.78 MJ/kg at 2.5 km/s. It equals the kinetic-energy gain ½(v_rel² − v_catch²) exactly.
- *Orbital energy*: the payload's specific orbital energy gain, ½(v_rel² − v_catch²) + μ(1/r_low − 1/r_tip) = 43.03 MJ/kg. With no dissipation the tether loses exactly what the payload gains, so this is what reboost must restore; Skyhook books its in-space fork this way (`finance/reboost_bound.py:118-120`). The difference, 5.246 MJ/kg (+13.9 %), is the lever-arm term: the payload's angular momentum about Earth grows by r_tip·v_rel − r_low·v_catch, not r_com·2v_tip.
- *n·ΔH*, mean motion times that angular-momentum gain (the work a tangential thrust at the CoM, moving at v_orb, does to restore it): 43.02, agreeing with the orbital view to 0.03 %.
- *Ground-relative catch*: the orbital view with v_orb − v_tip − 0.465, a frame mix-up: 45.27. Shown only because it is the nearest principled reading to MP-001.
- *Stated*: 44.8 MJ/kg = 12.4 kWh/kg "of mechanical energy" (`docs/research/mp001_market_pricing.md:37`, labelled [Anchored]; the note says at `:6` that everything in it is secondary-sourced desk research); "~30 MJ/kg" (`docs/project_instructions.md:218`, `tools/sims/skyhook_program_site.html:648`). Electrical placeholders: 48 kWh/kg (MP-001 `:37`, `docs/research/perplexity_research_brief.md:75`, `docs/program_manifest.md:53, :65`) and 33 kWh/kg, the default in the simulator `CLAUDE.md` calls canonical (`tools/sims/skyhook_no_leo_stress_test.jsx:58`).
- *Sweep* (`model.reboostSweep`): 3 radii (6,371, 6,378, 6,378.137) × v_orb computed or printed (7.55) × release computed or printed (10.06) × catch inertial, ground-relative or printed (4.59) × potential term none, two-body, g0·2L or g(r_com)·2L = 144 readings. None rounds to 44.8; the nearest is 45.19 (printed v_orb and catch speed, uniform g at the CoM). Where 44.8 comes from is not in the repository.
- *What the decision grid prices*: `finance/decision_grid.json` publishes `reboost_electricity_per_kg` per tier and ladder column. E/η/3.6 × $/kWh with η and $/kWh from the workbook's Assumptions rows 6 and 7 (0.15/0.20/0.30 and 0.08/0.06/0.04) reproduces all nine at four decimals with E = 2·v_orb·v_tip on the 6,371 km Earth (5.5973, 3.1485, 1.3993; 6.2689, …), none on Aster's (5.5944, …), and the published line divided by v_tip is constant within a column to 2×10⁻⁵ (linear in v_tip, which the orbital view is not). Booking the orbital energy instead adds $0.78 / $0.44 / $0.19 per kg (conservative / baseline / optimistic), 2.8–4.4 % of the marginal cost ($17.60/kg conservative at the reference tier). The grid's mass ratios also reproduce at four decimals (121.8261, 64.3046, 40.3214, 295.2697, …, 3,085.9535).

**Data and provenance.** The numbers the arithmetic reads are snapshots with sidecars from the bank's `tools/snapshot.mjs`: `snapshots/rev_a.json` and `snapshots/delta-v.ts` whole; line-preserving excerpts (registry lines verbatim, every other line empty, named `.lines.txt` so the checker never runs an excerpt of a test file) of `physics/skyhook_physics.py`, `docs/research/mp001_market_pricing.md`, Aster's `main.ts`, `launch-vehicles.ts`, `SLICE_11_FOUNDING.md` and the audit report; `snapshots/workbook-assumptions.json` (rows 2, 3, 6, 7, 15 of the workbook's Assumptions sheet, read with Node's zlib and the zip directory, no openpyxl); `snapshots/decision-grid-excerpt.json` (the first point of each of the nine series; mass ratio and reboost do not vary along a series). All at Aster `62ddb17` and Skyhook `34935cb`, every read matching the committed blob. The other 70 rows are citations: `data.js` records their line text and both commits from the last live run, and `--offline` reports them as `saved`, not re-verified. `data.js` also carries the scan summary the page shows.

**The page.** Six headline tiles, a strip plot of the six distinct radii (tap or hover a dot for its sources), a picker that recomputes `rev_a.json` on any μ, radius and rotation speed the concordance holds (refusing the ground-relative speed when no rotation rate is chosen), the interface table and a bar chart of the C3 shift by cause, the reboost tables, the concordance filterable by constant and repository (each site opens to its line as read), and the gates. `app.js` holds no constant; a test greps it and `index.html` for 14 of them.

## Honest assessment

- **[Certain] The concordance is complete for its scope at these commits.** Every one of the 94 rows was read on its line, and the scan of 566 Aster and 73 Skyhook files found no occurrence the registry does not list. "Complete" means: these patterns, these files. A constant written another way (`3986004.418e8`, "about 6,400 km") or in an excluded file would not be seen; the exclusions are listed with their reasons.
- **[Certain] The arithmetic.** Two-body formulas mirroring Skyhook's module and Aster's `injectionDvFromC3`, reconciled with 34 printed canon values, nine grid rows to four decimals, Aster's four published injection values, A&S Table 7.1 and closed forms, and recomputed independently in Python.
- **[Certain] μ does not matter at this interface; the radius convention does, and mostly for reproducibility.** A 1.1×10⁻⁶ difference in μ moves C3 by 4×10⁻⁵ km²/s². The 7.137 km radius difference moves C3 by 0.02–0.03 and the cislunar apogee by 5,730 km, enough that a consumer recomputing the canon on Aster's Earth will not reproduce its printed C3 (−8.03 against −8.06) or apogees. Mixing the two Earths is worse than either (0.107; 23,961 km).
- **[Certain] Earth rotation enters none of the K2 quantities computed here.** Every one is inertial (upper-tip release and arrival energy). It matters for the ascending lower-tip catch only, which is Skyhook-internal.
- **[Certain] The finance model's reboost line is the momentum view on the 6,371 km Earth**: the grid reproduces only that way.
- **[Likely] The orbital-energy figure (43.03 MJ/kg at 2.5 km/s) is the right per-kilogram energy for reboost**, under the canon's own kinematic model (rigid rotation, no dissipation, catch and release at matched speed). It is an energy bound; how an electrodynamic tether restores energy and angular momentum together is not modelled here, as `finance/reboost_bound.py`'s own scope line says of its bound. The difference is small money: $0.19–0.78 per kg against a $17.60/kg conservative marginal cost.
- **[Likely] MP-001's 44.8 MJ/kg did not come from the canon.** None of 144 readings reproduces it; I cannot rule out a reading I did not think of. MP-001 is labelled secondary-sourced desk research.
- **[Speculative] Which Earth K2 should pick.** Aster's (WGS84 a, already the porkchop's) would move the canon's printed C3s; Skyhook's (mean radius) would leave Aster's published injection values unreproduced at four figures. Either is defensible; recording the choice in the interface's assumptions is what matters.
- **Rough.** The registry is curated by hand; a reviewer can disagree with a role or kind (is `docs/program_manifest.md` "docs"? are the PCK comment lines worth listing?). The energy family mixes mechanical and electrical figures in one list, separated by unit. The sweep is a search for a reproduction, not a proof that none exists. The page's 70 citation rows come from the saved run, not a live read (a browser cannot read the checkouts). ## Deviations from the judged proposal, and why

- **The C3 shift under R = 6,378.137 is 0.021–0.029 km²/s², not ≈0.11.** The proposal's 0.11 (1.3 % of −8.06) holds only if v_orb stays on the 6,371 km Earth while r_tip moves, as the third judge noted. Both are computed and tested: 0.0290 / 0.0267 / 0.0213 consistent, 0.1066 mixed for every tier. The proposal's test band (0.10–0.12 for every tier) is applied to the mixed reading only.
- **The candidate explanation for 44.8 MJ/kg does not reproduce it.** Adding the 290→930 km potential term to 2·v_orb·v_tip gives 43.03; also using the ground-relative catch speed gives 45.27. Neither rounds to 44.8, and neither does anything else in a 144-reading sweep (nearest 45.19). Reported as "does not agree; source not in the repository".
- **Citations corrected.** Aster's INV-025 (`INVARIANTS.md:199`) is the public-copy taxonomy rule, not number provenance; the applicable invariant is INV-026 (`:200`). INV-021 is about the frame of vector components, so it applies here only by analogy. (The bank's `BRIEFING.md` glosses INV-025/026 together as provenance; that gloss is loose for INV-025.)
- **Scope widened where the proposal's own question led.** The proposal named five constants in two places each; the registry holds 94 statements, including Skyhook simulators using Aster's μ and g = 9.81 (findings 4, 5), Aster's three radii and its NAIF kernel (finding 7), the founding-document and simulator reboost figures (findings 2, 3), and Aster's published injection values, which became pins. The decision grid and three of the workbook's ladder rows (3, 6, 7) were added because they are where the 37.78 MJ/kg actually reaches a published number.
- **Data.** The proposal planned two snapshots (`rev_a.json`, `delta-v.ts`) and under 30 KB. The arithmetic also reads the physics module's literals, Aster's parking altitude and g0, the pins' text, the workbook rows and the grid, so those are snapshotted too (10 snapshots, 26 KB with sidecars). The 70 citation-only rows are verified live and recorded in `data.js` rather than snapshotted file by file, to keep the folder small.
- **"Recompute every [Certain] derived number"** is done for every number that follows from the file's own inputs, with two refused (the GTO and TLI threshold speeds need a target radius the file does not state); this overlaps idea 04's `--verify-canon`, so the new part is the second and third Earth.
- **Surface.** The proposal said CLI; the CLI is the instrument and `example.txt` its output, and a page was added because the picker (recompute the canon on any Earth the repositories state) and the filterable concordance read better in a browser.
